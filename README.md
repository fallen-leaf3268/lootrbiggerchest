# Lootr Bigger Chest

扩展 Lootr 箱子、木桶、潜影盒和运输矿车的容量，支持固定尺寸或加权随机尺寸。新建的 Lootr 自定义库存及 `MenuBuilder` 入口沿用 Lootr 原有行为。

## 兼容的容器

| 容器 | 原版尺寸 | 行范围 | 列范围 |
|------|---------|-------|-------|
| Lootr 箱子 | 3×9 | 1~20 | 1~32 |
| Lootr 木桶 | 3×9 | 1~20 | 1~32 |
| Lootr 潜影盒 | 3×9 | 1~20 | 1~32 |
| Lootr 运输矿车 | 3×9 | 1~20 | 1~32 |

## 依赖

- **Minecraft** 1.20.1
- **Forge** 47.3+
- **Lootr** 0.7+

## 配置

配置文件位于 `config/lootrbiggerchest-common.toml`：

### 固定尺寸

```toml
["箱子"]
行数 = 3     # 1 ~ 20
列数 = 9     # 1 ~ 32
```

四种容器（箱子、木桶、潜影盒、箱子矿车）各自独立配置。

### 随机尺寸

若配置了 `随机容量` 列表，则忽略固定行列，从列表中按权重随机选取：

```toml
["箱子"]
随机容量 = ["3,9,50", "6,9,30", "9,12,20"]
# 格式: "行,列,权重"
# 留空则使用固定行列
```

每个容器在首次打开时确定尺寸并持久化保存。

### 玩家独立容器大小

```toml
玩家独立容器大小 = false
```

默认关闭。开启后，每个 Lootr 容器会为每名玩家在首次生成库存时，使用该容器类型的随机容量池独立计算一次尺寸并持久化；随机池为空时使用固定尺寸。

- 同一玩家再次打开同一容器时沿用原尺寸
- Lootr 刷新库存只刷新物品，不重新随机尺寸
- 关闭配置后，已有玩家尺寸保留，新玩家使用公共容器尺寸
- 旧玩家库存不会因开启该配置而重新随机或缩容
- 新建自定义容器和 `MenuBuilder` 入口保持 Lootr 原有行为
- 旧版扩展过的自定义库存保留既有容量与物品；带尺寸记录的库存继续按原尺寸打开

## 注意事项

- 配置修改后即时生效，无需重启
- 已存在的旧容器保持首次打开时确定的尺寸不变
- 容器 GUI 由代码拼接原版箱子材质，超出当前窗口时自动缩放

## 导出与替换完整 GUI

在客户端执行 `/lootrbiggerchest ui export chest 6 12`，导出 6 行 12 列的完整界面背景。类型可选 `chest`、`barrel`、`shulker`、`minecart`，行数为 1~20，列数为 1~32。

文件生成在当前版本实例目录的 `lootrbiggerchest/exports/chest/6x12.png`。根目录使用启动器传入的游戏目录；启用版本隔离时即为对应版本目录。导出只生成 PNG，不自动创建资源包，已有图片不会被覆盖。

直接编辑 PNG，保留图片尺寸和槽位位置。玩家决定使用时，再将图片复制到自己的资源包中，例如 `assets/lootrbiggerchest/textures/gui/chest/6x12.png`，然后启用资源包并重载资源。导出目录不会被自动加载。图片包含容器与玩家物品栏背景；标题、物品及提示由游戏绘制。

四类容器分别使用自己的目录，按行数和列数匹配完整 PNG。未提供图片、图片无法读取或尺寸不符时，使用默认代码绘制；不会借用其它类型或尺寸的图片。
